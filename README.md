# MLOPS_CLA-4
# ML Model Deployment Strategies and Model Serving using FastAPI

This project implements the CLA 4 assignment using the **Titanic – Machine Learning from Disaster** dataset. It trains one classification pipeline, saves it as `model.pkl`, reuses that same pipeline for online, batch, and streaming inference, and serves predictions through FastAPI.

## Dataset

Download **`train.csv`** from the official Kaggle competition data page:
https://www.kaggle.com/competitions/titanic/data

Place it here: `data/train.csv`

Do not upload a Kaggle password, API token, or other credentials.

## Setup

Use Python 3.10 or newer. Open a terminal in this project folder.

### 1. Install dependencies

```bash
python -m venv .venv
```

Windows:
```bash
.venv\Scripts\activate
```

macOS/Linux:
```bash
source .venv/bin/activate
```

Then:
```bash
pip install -r requirements.txt
```

### 2. Download the dataset

Download `train.csv` from Kaggle and put it inside the `data` folder.

### 3. Train and evaluate the model

```bash
python train_model.py
```

This trains a Random Forest classification pipeline, evaluates accuracy on a held-out test split, and creates `model.pkl`, `data/unseen_passengers.csv`, and `outputs/evaluation.txt`. The inference records come from the held-out portion and were not used to fit the model.

### 4. Run online inference

```bash
python online_inference.py
```

One unseen passenger is predicted.

### 5. Run batch inference

```bash
python batch_inference.py
```

Predictions for 20 held-out passenger records are printed and saved to `outputs/batch_predictions.csv`.

### 6. Run streaming inference

```bash
python streaming_inference.py
```

Ten held-out records are processed one at a time, with a one-second delay.

### 7. Start the FastAPI server

```bash
uvicorn app:app --reload
```

Open Swagger UI: http://127.0.0.1:8000/docs

Test:
- `GET /health`
- `POST /predict`

Example valid request body for `/predict`:

```json
{
  "Pclass": 3,
  "Sex": "female",
  "Age": 22,
  "SibSp": 1,
  "Parch": 0,
  "Fare": 7.25,
  "Embarked": "S"
}
```

To demonstrate validation, submit an invalid request such as `Pclass: 9` or `Sex: "unknown"` and capture the validation error.

### 8. Test using the Python client

Keep the API server running in one terminal. In a second terminal, run:

```bash
python client.py
```

## Assignment observations

1. **Online vs. batch inference:** Online inference predicts one request/record at a time and is useful for immediate responses. Batch inference processes a group of records together and is useful for bulk processing.
2. **Streaming vs. batch inference:** Streaming inference processes records as they arrive, continuously or one at a time. Batch inference waits for a group of records and processes them together.
3. **Why FastAPI?** FastAPI makes it straightforward to expose model predictions through HTTP endpoints, validate request data with Pydantic, and test endpoints using automatically generated Swagger UI documentation.
4. **Why reuse the same model?** Reusing the same saved pipeline keeps predictions consistent across inference strategies and API requests, avoids unnecessary retraining, and ensures preprocessing remains the same.
